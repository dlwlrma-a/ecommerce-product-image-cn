# 商品一致性与参考图覆盖

在需求访谈和计划生成前使用本指南。参考图是商品事实证据，不是开始工作的门票。先用已有证据设计可执行构图，再把补图作为提升选项；未展示的商品表面、结构和细节仍不能靠模型猜测。

## 基本原则

- 所有参考图必须是同一 SKU、颜色、材质、包装版本和配件组合。不同颜色、尺码设计或包装版本分批处理。
- 先检查图片内容，再标注角色；不要只根据文件名判断。支持 `front`、`back`、`left`、`right`、`side`、`top`、`bottom`、`detail`、`packaging`、`label`、`scale`。
- 计划中的成图只展示已有证据覆盖的视角。缺少推荐视角时，优先改变机位、裁切或商品朝向，使未知表面不入镜，同时给出补图建议。
- 最多可使用 16 张参考图，但不要求凑数。清晰、无强滤镜、无遮挡、不同有效视角的图片优先于大量重复图。
- 同一计划中的每个镜头都应携带这套 SKU 的完整参考图集合。镜头级 `reference_roles` 表示该构图的最低证据要求，不应被当成筛选器而丢弃其他参考视角。

## 品类建议

| 品类 | 完整套图建议的最低覆盖 |
| --- | --- |
| 服装 | 正面、背面、侧面或版型轮廓、面料/图案/纽扣/拉链细节；不对称结构两侧都要有 |
| 鞋靴 | 正面、外侧、内侧、后跟、鞋底、材质与 Logo 细节 |
| 箱包 | 正面、背面、侧面、顶部/开合、内部结构、五金与 Logo 细节 |
| 电子/家电 | 正面、背面、侧面、接口、按键、屏幕、铭牌和随附配件 |
| 食品/美妆/包装商品 | 包装正面、背面、侧面、标签文字、封口、内容物或质地；包装文字必须可读 |
| 多部件套装 | 整套合照以及每个包含部件、连接方式和包装清单 |

这些是高一致性完整套图的建议覆盖，不是当前方案的硬门槛。`--required-view` 或商品档案中的 `required_views` 用于记录希望补齐的视角；缺失时计划标记为 `limited`，仍可生成受现有证据约束的镜头。

## 资源自适应示例

- 只有衣服背面图：先给背面白底展示、背面卖点图、背向或侧后方场景图；建议补 `front` 以解锁正面主图和正面模特图。
- 有服装正面但没有背面：先给正面与可见细节方案，避免后领、后腰、开衩或背部图案入镜；建议补 `back` 以扩展完整套图。
- 没有高清细节图：可以基于当前清晰可见区域做保守裁切，但将高倍率材质、五金或接口特写列为补 `detail` 后可生成。
- 某个 `shots.reference_roles` 明确要求缺失视角：只把该镜头放入 `deferred_shots`，其余镜头继续。
- 参考图混有不同颜色或版本：这是 SKU 事实冲突，必须先让用户指定本批次 SKU；不能把不同商品混在一个参考集里。

## 命令标注

每张本地或远程参考图都使用 `ROLE=VALUE`：

```powershell
--reference-file "front=.\front.jpg" --reference-file "back=.\back.jpg" --reference-file "detail=.\fabric.jpg"
--reference-url "side=https://example.com/product-side.jpg"
```

服装等高风险品类会自动给出建议视角。其他品类可根据希望扩展的构图追加，例如：

```powershell
--required-view front --required-view back --required-view side --required-view detail
```

## 生成后审计

逐张成图与对应参考图并排检查：

1. 整体轮廓、长宽比例、部件数量和相对位置。
2. 正背面结构、领口、袖型、接缝、开合、纽扣、拉链、接口和配件。
3. 颜色、图案方向、材质纹理、透明与反光区域。
4. Logo、标签、包装文字、型号和尺寸。
5. 场景中的尺度、握持/穿戴关系和物理接触是否合理。

任何关键项不一致，都标记该图失败并只重做该图；不要把不一致结果作为新的参考事实。没有人工或视觉能力完成对照时，明确标记“保真未验收”，不得声称已经保持一致。
